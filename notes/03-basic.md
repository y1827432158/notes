# 三、基础算法模板

## 3.1 快速排序（手写）

- 分治：选基准 `x`，把区间分成「≤ x」和「≥ x」两半，再分别递归
- 平均 O(n log n)，最坏 O(n²)；**原地排序、不稳定**
- 全程用**闭区间** `[l, r]`

```cpp
void quick_sort(int q[], int l, int r) {
    if (l >= r) return;                  // 0 或 1 个元素，不用排
    int x = q[l], i = l - 1, j = r + 1;  // i、j 先站到区间外

    while (i < j) {
        do i++; while (q[i] < x);        // 从左找第一个 >= x 的
        do j--; while (q[j] > x);        // 从右找第一个 <= x 的
        if (i < j) swap(q[i], q[j]);     // 两边都停下才交换
    }
    quick_sort(q, l, j);                 // 左半 [l, j]
    quick_sort(q, j + 1, r);             // 右半 [j+1, r]
}
```

**为什么这么写**

| 写法 | 原因 |
| --- | --- |
| `i = l - 1, j = r + 1` 配 `do i++` | 第一轮正好指向 `l` 和 `r`，省掉特判 |
| 用 `do-while` 而不是 `while` | 保证至少动一格；`while` 会在 `q[i] == x` 时卡住不动，死循环 |
| 比较写**严格** `<` / `>` | 等于基准的元素也停下参与交换 → 等于 `x` 的值被均匀分到两侧，**这是避免最坏 O(n²) 的关键** |
| `int x = q[l]` 存成变量 | 直接拿 `q[l]` 比较的话，交换之后基准就漂了 |

**递归边界（最容易写错的地方）**

- 基准取**左端** `q[l]` → 只能用 `j` 分：`[l, j]` 和 `[j+1, r]`
- 写成 `[l, i-1]` 和 `[i, r]` 会**无限递归**：以 `[1, 2]` 为例，循环结束时 `i == l == 0`，右半边 `[i, r]` 还是原区间，永远缩不小
- 口诀：基准取**左端** `q[l]` 就用 `j` 分，取**右端** `q[r]` 就用 `i` 分；取中间 `q[(l+r)/2]` 两者皆可
- `if (l >= r) return;` 不能省 —— 单元素区间 `[k, k]` 用 `j` 分会退化成 `[k, k]` 加一个空区间，自己递归自己

**易错点**

- 分界变量**不对称**：用了 `j` 就一路 `j`，别一半 `i` 一半 `j`
- 循环条件 `while (i < j)` 不能写成 `<=`
- 快排**不稳定**（相等元素的相对次序会变），要保序用归并 / `stable_sort`
- 比赛里直接用 `sort`（内省排序，最坏也是 O(n log n)）；手写快排是为了理解分治、应付手写题
- **调用传的是闭区间**：`quick_sort(q, 0, n - 1)`。传 `n` 会多算一个越界元素，不报错但答案错
- 数组怎么开见 3.3

## 3.2 快速选择（求第 k 小数）

- 用途：**无序**数组求第 `k` 小，平均 **O(n)** —— 比「先整体排序再取」的 O(n log n) 更快
- 做法：分区之后**只递归目标所在的那一边**，另一半整个丢掉
- `k` 从 **1** 开始编号；第 k 大 = 第 `n - k + 1` 小

```cpp
int quick_select(int q[], int l, int r, int k) {
    if (l == r) return q[l];
    int x = q[l], i = l - 1, j = r + 1;

    while (i < j) {                               // 分区部分和快排一模一样
        do i++; while (q[i] < x);
        do j--; while (q[j] > x);
        if (i < j) swap(q[i], q[j]);
    }
    int sl = j - l + 1;                           // 左半边的元素个数
    if (k <= sl) return quick_select(q, l, j, k);         // 在左边：仍是第 k 小
    return quick_select(q, j + 1, r, k - sl);             // 在右边：变成第 k-sl 小
}
```

**为什么是 O(n)**：每层只处理一半，`n + n/2 + n/4 + … = 2n`（快排是每层处理全部，所以多一个 log）

**和快排的区别**

| | 快速排序 | 快速选择 |
| --- | --- | --- |
| 递归 | 左右都递归 | **只递归一边** |
| 时间 | O(n log n) | 平均 O(n)，最坏 O(n²) |
| 产出 | 整个数组有序 | 只求出第 k 个 |

**STL 版本**

```cpp
nth_element(v.begin(), v.begin() + k, v.end());   // 第 k 小（0 基）就位
```

- 结束后下标 `k` 上就是第 k 小，左边都不大于它、右边都不小于它，但**两边不保证有序**
- 求前 k 小：`nth_element` 之后取 `[0, k)`，需要有序再 `sort` 这 k 个
- 实现是内省选择，平均和最坏都是 O(n)，比自己手写稳

**易错点**

- 分区照抄快排，所以分界点的坑完全一样：基准取左端 `q[l]` 就只能用 `j` 分
- 调用同样是**闭区间**：`quick_select(q, 0, n - 1, k)`
- `k` 是 **1 基**，而 `nth_element` 是 **0 基**，两边换算别差一位
- 最坏 O(n²)：输入有序 + 基准取 `q[l]` 时每轮只缩 1 个，换 `q[(l+r)/2]` 更稳
- **会打乱原数组**（原地分区），后面还要用原顺序就别用
- 数据是**流式**的、或不能改原数组 → 用小顶堆 O(n log k)
- AcWing 786「第 k 个数」就是这个模板

## 3.3 大数组怎么开：`const` 与全局

**为什么 `int N = 100000; int q[N];` 编译不过**

- 数组长度要的是**编译期常量**，而 `int N` 定义的是**变量**
- `N = 5;` 是合法语句；全局非 `const` 变量还是**外部链接**（别的 `.cpp` 写 `extern int N;` 就能改）—— 编译器没法假设它不变
- 所以标准规定数组维度必须是**常量表达式**。编译器在优化阶段确实会把 `N` 替换成 `100000`，但那是**优化，不是语义**，语法检查这关照样拦

```cpp
int N = 100000;          // 变量：值随时能改
int q[N];                // ✗ 编译期算不出要分配多少字节

const int N = 100000;    // 常量：编译期定死
int q[N];                // ✓
```

| 写法 | 能否当数组长度 |
| --- | --- |
| `int N = 1e5;` | ✗ 是变量 |
| `const int N = 1e5;` | ✓ C++ 可以 |
| `constexpr int N = 1e5;` | ✓ C++11，语义最明确 |
| `#define N 100010` / `enum { N = 100010 };` | ✓ |
| 字面量 `int q[100000]` | ✓ |

**C 和 C++ 不一样**：C 里的 `const` 只是「只读变量」，`const int N = 1e5; int q[N];` 在 C 里**编译不过**，得用 `#define` 或 `enum`。别把 C 的规则套过来。

**为什么必须放全局**

- 全局数组在**静态存储区**，开多大都不占栈，还自动清零
- 写在函数里：100000 个 `int` = 400KB，而默认栈只有 1MB，n 再大点就**爆栈**——评测机报 RE / 段错误，很难查到原因

**别依赖 GCC 的 VLA 扩展**

```cpp
int main() {
    int n; cin >> n;
    int q[n];       // GCC 扩展放过去了，但非标准 + 栈上分配
}
```

- 只在**函数内**有效；写在全局时连 GCC 都不放行（全局变量大小必须编译期定死），所以那种写法在全局是**硬编译错误**
- MSVC 直接报错，Clang 只当扩展容忍

**模板**

```cpp
const int N = 1e5 + 10;   // 多开 10 个，防差一（闭区间传参、前缀和从 1 开始……）
int q[N];                 // 全局
```

## 3.4 归并排序与逆序对

**归并排序**

- 分治：从**中点**劈成两半 → 各自递归排好 → **合并两个有序段**（合并是 O(n)）
- **恒 O(n log n)**（最坏也是）；代价是 **O(n) 辅助空间**；**稳定**
- 闭区间 `[l, r]`，分界固定是 `mid`，没有快排那种「取哪端配哪个变量」的坑

```cpp
const int N = 1e5 + 10;
int q[N], tmp[N];                    // tmp 必须开全局（见 3.3）

void merge_sort(int q[], int l, int r) {
    if (l >= r) return;

    int mid = l + r >> 1;
    merge_sort(q, l, mid);
    merge_sort(q, mid + 1, r);

    int k = 0, i = l, j = mid + 1;   // 合并两个有序段到 tmp
    while (i <= mid && j <= r) {
        if (q[i] <= q[j]) tmp[k++] = q[i++];   // <= 才稳定
        else              tmp[k++] = q[j++];
    }
    while (i <= mid) tmp[k++] = q[i++];        // 收尾：纯搬运，不干别的
    while (j <= r)   tmp[k++] = q[j++];

    for (i = l, k = 0; i <= r; i++, k++) q[i] = tmp[k];   // 拷回，别忘
}
```

**核心操作：合并两个有序段**

```text
左段 [1, 3, 7]       右段 [2, 4, 6]
     i↑                   j↑
比 1 和 2 取 1；比 3 和 2 取 2；比 3 和 4 取 3 …… → [1, 2, 3, 4, 6, 7]
```

两段各自有序 → 双指针谁小取谁，一趟就合并完。

**和快排的区别**

| | 快速排序 | 归并排序 |
| --- | --- | --- |
| 怎么分 | 按**值**分（partition） | 按**位置**分（中点劈开） |
| 何时排好 | 分完就定位 | **合并**时才排好 |
| 分界点 | 取哪端配哪个变量，有坑 | 固定 `mid`，无坑 |
| 时间 | 平均 O(n log n)，最坏 O(n²) | **恒 O(n log n)** |
| 空间 | O(log n) 栈，原地 | **O(n)** 辅助数组 |
| 稳定性 | 不稳定 | **稳定** |

- 快排「先苦后甜」（分区费劲，分完就不管了）；归并「先甜后苦」（先递归到底，回来时才合并）

**易错点**

- `tmp` 开**全局**（见 3.3）；**拷回 `q` 那一步不能忘**，忘了等于没排
- 合并比较写 `<=` 才稳定，写 `<` 会把相等元素的次序打乱
- 分界**只能**是 `[l, mid]` + `[mid+1, r]`：`mid` 是按位置定死的，别把快排那套 `j` 搬过来

**逆序对（AcWing 788）**

- 定义：`i < j` 且 `a[i] > a[j]` 的数对
- 分段计数：**总逆序对 = 左段内部 + 右段内部 + 跨两段的**
- 段内的交给递归；**跨段的在合并那一刻一次数清**

```text
左段 [2, 3, 4]       右段 [1, 5, 6]
     i↑                   j↑
q[i] = 2 > q[j] = 1
```

左段是递增的，`q[i] > q[j]` 就意味着 `q[i..mid]` **全部**大于 `q[j]`，而下标都比 `j` 小 —— 一次就是 `mid - i + 1` 个。

```cpp
typedef long long LL;                // 答案最大约 5×10⁹，必须 long long

LL merge_sort(int q[], int l, int r) {
    if (l >= r) return 0;

    int mid = l + r >> 1;
    LL res = merge_sort(q, l, mid) + merge_sort(q, mid + 1, r);   // ← 子段的要接住

    int k = 0, i = l, j = mid + 1;
    while (i <= mid && j <= r) {
        if (q[i] <= q[j]) tmp[k++] = q[i++];
        else {
            res += mid - i + 1;      // ← 整段一起加
            tmp[k++] = q[j++];
        }
    }
    while (i <= mid) tmp[k++] = q[i++];    // ← 收尾不加 res
    while (j <= r)   tmp[k++] = q[j++];

    for (i = l, k = 0; i <= r; i++, k++) q[i] = tmp[k];
    return res;
}
```

**逆序对的易错点**

- **`long long`**：`n = 1e5` 时最多 `n(n-1)/2 ≈ 5×10⁹`，而 `int` 上限只有 2.1×10⁹
- **递归返回值必须接住**：`res = 左 + 右`。只写 `merge_sort(...)` 不接收，子段数出来的全丢
- **`res += mid - i + 1`，不是 `res++`**：一次是一整段，不是 1 个
- **收尾的 `while` 不加 `res`**：搬运剩余元素不产生新的跨段逆序对
- `<=` 不能写成 `<`：题目要**严格** `a[i] > a[j]`，写 `<` 会把相等的也算进去
  - 这个坑在样例 `2 3 4 5 6 1`（无重复数字）上**看不出来**，交上去遇到重复数据才 WA

## 3.5 整数二分

- 用武之地：区间有**二段性** —— 能用一个性质把区间劈成两半，一半全满足、一半全不满足，**分界点就是答案**
- 「有序」只是最常见的特例（性质取 `q[mid] >= x`）；二分的本质是二段性，不要求有序
- 复杂度 **O(log n)**。写法有两个模板，分别对应「找左分界」和「找右分界」

**`check(mid)` 不是库函数**

- 它是模板里的**占位符**，代表「你按题目写的那句判断条件」—— 既不用 `#include`，也不用自己定义
- **骨架**（`while (l < r)`、`mid` 怎么取、区间怎么缩）所有题都一样；**`check` 每题都不一样**。简单题直接把条件填进 `if`：

```cpp
if (check(mid)) r = mid;        // 模板里的写法
if (q[mid] >= x) r = mid;       // 789 里的实际写法：check(mid) 就是 q[mid] >= x
```

- 只有条件复杂到一行写不下时，才真的定义一个函数 —— 这就是**二分答案**（「最大的最小 / 最小的最大」那类题），函数名随便叫：

```cpp
bool check(int mid) {           // 例：分巧克力 —— 边长取 mid 够不够切出 k 块
    int cnt = 0;
    for (int i = 0; i < n; i++) cnt += (h[i] / mid) * (w[i] / mid);
    return cnt >= k;
}
```

**模板一：找左分界**（**第一个**满足 `check` 的位置）

```cpp
int l = 0, r = n - 1;
while (l < r) {
    int mid = l + r >> 1;          // 下取整
    if (check(mid)) r = mid;       // mid 满足 → 答案在 [l, mid]
    else            l = mid + 1;   // 不满足   → 答案在 [mid+1, r]
}
// 结束时 l == r，就是答案
```

**模板二：找右分界**（**最后一个**满足 `check` 的位置）

```cpp
int l = 0, r = n - 1;
while (l < r) {
    int mid = l + r + 1 >> 1;      // ← 上取整，必须 +1
    if (check(mid)) l = mid;       // mid 满足 → 答案在 [mid, r]
    else            r = mid - 1;
}
```

**为什么模板二要 +1**

`(l + r) / 2` 是**向下取整**。当 `l = r - 1` 时 `mid = l`，模板二这一轮若走 `l = mid`，`l` 原地不动 → **死循环**。改成上取整 `(l + r + 1) / 2` 后 `mid = r`，区间必定缩小。

| 收缩写法 | `mid` 归哪一半 | 取整 |
| --- | --- | --- |
| `r = mid` / `l = mid + 1` | 左半 `[l, mid]` | 下取整 |
| `l = mid` / `r = mid - 1` | 右半 `[mid, r]` | 上取整，**+1** |

**口诀：写了 `l = mid` 就加 1。**

**应用：AcWing 789 数的范围**（升序数组里查 x 的起止下标）

两次二分：先找**第一个 `>= x`**，再找**最后一个 `<= x`**。

```cpp
// ① 左边界：第一个 >= x
int l = 0, r = n - 1;
while (l < r) {
    int mid = l + r >> 1;
    if (q[mid] >= x) r = mid;
    else             l = mid + 1;
}
if (q[l] != x) { cout << "-1 -1\n"; continue; }   // 没找到
cout << l << ' ';

// ② 右边界：最后一个 <= x
l = 0, r = n - 1;
while (l < r) {
    int mid = l + r + 1 >> 1;      // +1，因为下面写的是 l = mid
    if (q[mid] <= x) l = mid;
    else             r = mid - 1;
}
cout << l << '\n';
```

**易错点**

- `while (l < r)`，不是 `<=`：结束时 `l == r` 就是答案，写 `<=` 会死循环
- 模板二的 `+1` 忘了 → **死循环**。不是答案错，是卡在原地不动，评测机报 TLE —— 很难看出问题出在二分
- `int mid = l + r >> 1` 靠的是 `+` 优先级高于 `>>`；不确定就老实写 `(l + r) / 2`
- 二分只定位**边界**，不保证那个位置上的值就是 x，**必须再判一次** `q[l] != x`
- 数组无序时二分的答案没有意义 —— 除非它有别的二段性
- 看到「**有序 + 多次查询**」就该想二分：本题暴力 O(nm) ≈ 10⁹ 必 TLE，二分 O(m log n) ≈ 1.7×10⁵

**浮点数二分**见 3.6

## 3.6 浮点数二分

- 和整数二分同一个骨架，但**三处不一样**：不用 `+1`、不用管取整、循环条件靠**精度阈值**
- 典型题：AcWing 790 数的三次方根

**模板（推荐）**

```cpp
double l = -10000, r = 10000;       // 区间必须覆盖答案（注意负数！）
while (r - l > 1e-8) {              // 阈值 = 题目精度 + 2 位
    double mid = (l + r) / 2;
    if (check(mid)) r = mid;        // 两种写法都行，都收敛到同一点
    else            l = mid;
}
printf("%.6lf\n", l);               // 结束时 l（或 r）就是答案
```

**阈值取多少：题目精度 + 2 位**

| 题目要求 | 阈值 |
| --- | --- |
| 保留 4 位小数 | `1e-6` |
| 保留 6 位小数 | **`1e-8`** |
| 保留 8 位小数 | `1e-10` |

- 二分停下时区间还剩下不到阈值那么长，取的点的误差也是这个量级。要 6 位小数可靠，误差必须远小于 `1e-6` —— 取 `1e-8` 留了 100 倍余量
- 阈值取得和精度同级（`1e-6`）可能让最后一位出错；**低于 `1e-15` 会死循环**：`l`、`r` 相邻到只差 1 ulp 时，`(l + r) / 2` 会等于 `l` 或 `r`，区间再也缩不动

**备用写法：固定迭代次数**

```cpp
for (int i = 0; i < 100; i++) {     // 次数写死，不用算阈值
    double mid = (l + r) / 2;
    if (check(mid)) r = mid;
    else            l = mid;
}
```

- 好处：**不用操心阈值**，也没有死循环风险；精度要求很高（10 位以上）或者答案量级不确定时更防呆
- 代价：本题 `while` 版约 41 次就收敛，这里固定跑 100 次 —— 但每次只是几步浮点运算，**性能上没有差别**

| | `while (r - l > 1e-8)` | 固定 100 次 |
| --- | --- | --- |
| 要不要算阈值 | 要（精度 + 2 位） | 不用 |
| 迭代次数 | 自适应，本题约 41 次 | 固定 100 次 |
| 语义 | 「区间够小了就停」 | 「迭代够多就行」 |

- **比赛优先用 `while` 版**（题解通用、语义清楚）；精度要求特别高、或不想赌阈值时，退回固定次数

**和整数二分的区别**

| | 整数二分 | 浮点数二分 |
| --- | --- | --- |
| `mid` | `l + r >> 1`，要纠结**要不要 +1** | `(l + r) / 2`，**不用管** |
| 循环条件 | `while (l < r)` | `while (r - l > 1e-8)`，或固定迭代次数 |
| 为什么 | 整数除法取整，`l = r - 1` 时 `mid` 可能等于 `l` → 死循环 | 浮点除法**永远落在中间**，区间必定缩小 |
| 左右分界 | `check` 写法不同，**结果不同** | 两种写法**收敛到同一个答案** |

**易错点**

- **区间必须覆盖答案**：写 `double l = 0, r = n;` 的话，`n = -1000` 时区间直接反了。用题目给的值域兜底（`-10000 ~ 10000`）
- 输出用 `printf("%.6lf\n", l)`，或 `cout << fixed << setprecision(6) << l`（见 1.9）
- 算 `mid³` 直接写 `mid * mid * mid`，别用 `pow` —— 慢，而且没必要

**顺带：`<cmath>` 里现成的函数**

| 函数 | 作用 |
| --- | --- |
| `sqrt(x)` | 平方根 |
| `cbrt(x)` | **立方根** —— AcWing 790 一行就过 |
| `pow(x, y)` | x 的 y 次方（浮点，慢；整数次方优先自己乘） |
| `fabs(x)` | 浮点绝对值 |
| `ceil(x)` / `floor(x)` | 向上 / 向下取整（返回的仍是 `double`） |
| `round(x)` | 四舍五入 |
| `log(x)` / `log2(x)` / `log10(x)` | 对数（`log` 是**自然对数**）；`exp(x)` 是 e 的 x 次方 |

```cpp
printf("%.6lf\n", cbrt(n));        // 790 直接这么写也能过
```

- 但库函数只在**恰好有现成公式**时好使；遇到「求方程的根」「最大的最小 / 最小的最大」这类套不出公式的题，**二分的思路才是主角**

## 3.7 高精度加法

- `long long` 上限约 9.2×10¹⁸（19 位），本题位数到 **10⁵** —— 存不下，**只能手写**
- 做法：`string` 读进来 → **倒着**存进数组 → 模拟竖式逐位相加
- 复杂度 **O(n)**。AcWing 高精度四连（791 加 / 792 减 / 793 乘 / 794 除）套路完全一样

**为什么倒着存（个位放下标 0）**

- 加法从**低位**往高位算，进位往高位走。倒着存之后「低位」正好是小下标，从左往右扫就是竖式的自然顺序
- 结果比原数多一位（`99 + 1 = 100`）时，直接 `push_back` 到**末尾**就行；正着存的话末尾进位要在开头插入，O(n) 搬移

```text
  9 9
+   1
-----
1 0 0

q1 = [9, 9]（倒着存）   q2 = [1]
i=0: decimal = 9 + 1 = 10 → res[0] = 0, decimal = 1   ← 这一列满 10，写 0 进 1
i=1: decimal = 1 + 9 = 10 → res[1] = 0, decimal = 1   ← i 超出 q2 的长度，被 if 挡住
循环结束，decimal = 1 还有剩 → res = [0, 0, 1]
倒着输出 → 100
```

**模板**

```cpp
// q1、q2 都是倒着存的（个位在下标 0），返回的 res 也是倒着存的
vector<int> add(vector<int> &q1, vector<int> &q2) {
    vector<int> res;
    int decimal = 0;                            // decimal = 这一列的和（进循环时是上一位的进位）

    // 谁长谁说了算：两个数还有任意一个没读完，就继续往下加
    for (int i = 0; i <= q1.size() - 1 || i <= q2.size() - 1; i++) {
        if (i < q1.size()) decimal += q1[i];    // 短的读完了就不加，防止越界
        if (i < q2.size()) decimal += q2[i];

        res.push_back(decimal % 10);            // 这一列要写下的数字（取个位）
        decimal /= 10;                          // 剩下的是进位，留给下一列
    }

    if (decimal) res.push_back(decimal);        // 最高位还有进位，比如 99 + 1 = 100
    return res;
}

int main() {
    string s1, s2;
    cin >> s1 >> s2;

    vector<int> q1, q2;
    for (int i = s1.size() - 1; i >= 0; i--) q1.push_back(s1[i] - '0');   // 倒着存，- '0' 把字符变成数字
    for (int j = s2.size() - 1; j >= 0; j--) q2.push_back(s2[j] - '0');

    auto q3 = add(q1, q2);

    for (int k = q3.size() - 1; k >= 0; k--) cout << q3[k];   // 倒着输出，数字之间不加任何分隔
    return 0;
}
```

**`decimal` 一个变量为什么够用**

它同时扮演两个角色：进循环时是**上一列的进位**（0 或 1），加完 `q1[i]`、`q2[i]` 之后变成**这一列的和**（最大 `9 + 9 + 1 = 19`）。

- `decimal % 10` = 这一列要写下的数字
- `decimal / 10` = 留给下一列的进位（和 < 10 时自动变 0）

不用单独开 `carry` 变量 —— `%` 和 `/` 各取所需。减法的借位也是同一个套路。

**易错点**

- **存反了 / 输出反了**：存的时候 `for` 从 `size() - 1` 倒着来，输出也得从 `res.size() - 1` 倒着来，两头都要记得倒
- **字符转数字忘 `- '0'`**：`s1[i]` 是 `char`，`'5'` 的值是 **53** 不是 5。不减 `'0'` 的话数组里装的是 ASCII 码，后面对不上
- **最高位进位不能丢**：`if (decimal) res.push_back(decimal);` 少了这行，`99 + 1` 输出 `00`。这是最容易漏的一步
- **`push_back(decimal % 10)` 不是 `push_back(decimal)`**：`decimal` 可能是 19，只能写一位
- **只能算非负整数**：本题限制「正整数（不含前导 0）」。带负号要另外判符号、比较大小时用不到
- **前导 0**：加法结果不会产生前导 0（本题两数都无前导 0 且非 0），但换成减法 / 乘法就得单独去掉
- 用 C 数组替代 `vector` 时，长度按 `const int N = 1e5 + 10` 开（见 3.3），**加法的结果最多比长的那个数多 1 位**

**别的语言**

```java
// Java 有现成的，本题一行过
System.out.println(new BigInteger(a).add(new BigInteger(b)));
```

- Python 的 `int` 自动变长，`print(int(a) + int(b))` 就完了
- **C++ 没有内置大整数**，只能像上面这样手写 —— 但正因为要手写，才考你竖式和进位

## 3.8 高精度减法

- 791 是加法，792 是减法 —— **减法比加法多三个坑**（下表）
- AcWing 792 的结果**可能为负**，所以判符号那一段躲不掉

| | 高精度加法（3.7） | 高精度减法 |
| --- | --- | --- |
| 顺序 | `a + b == b + a`，谁前谁后无所谓 | **必须先比大小**，小减大要换过来再补负号 |
| 中间变量 | 进位，永远非负（0 或 1） | 借位，这一列的结果**可能为负** |
| 前导 0 | 不会产生，不用管 | **必须去掉**，`100 - 99` 逐位算出来是 `001` |

**① 先比大小**

```cpp
// A、B 倒着存且无前导 0，判断 A >= B
bool cmp(vector<int> &A, vector<int> &B) {
    if (A.size() != B.size()) return A.size() > B.size();   // 长度就是大小的第一判据
    for (int i = A.size() - 1; i >= 0; i--)                  // 等长就从最高位往下比
        if (A[i] != B[i]) return A[i] > B[i];
    return true;                                             // 完全相等
}
```

- 「先比长度」成立的前提是**输入不含前导 0**。要是允许 `007` 那种，得先去零再比

**② 减法主体**

```cpp
// 计算 A - B，前提：A >= B
vector<int> sub(vector<int> &A, vector<int> &B) {
    vector<int> C;
    int t = 0;                                            // t = 上一位借走的量（0 或 1）
    for (int i = 0; i < A.size(); i++) {
        t = A[i] - t;                                     // 被减数先还掉上一位借的
        if (i < B.size()) t -= B[i];
        C.push_back((t + 10) % 10);                       // ← 借位后统一变成非负
        t = (t < 0);                                      // ← 借了就是 1，没借是 0
    }
    while (C.size() > 1 && C.back() == 0) C.pop_back();   // 去前导 0
    return C;
}
```

- 已经保证了 `A >= B`，循环只跑到 `A.size()`；`B` 用 `if (i < B.size())` 兜住 —— 比加法还少一个分支

**③ `(t + 10) % 10` 是怎么来的**

`t = A[i] - 借位(0或1) - B[i]`，最大 `9 - 0 - 0 = 9`、最小 `0 - 1 - 9 = -10`，所以 **`t ∈ [-10, 9]`**：

| `t` | `(t + 10) % 10` | 为什么 |
| --- | --- | --- |
| `t >= 0` | `= t` | `t + 10 ∈ [10, 19]`，取模又减回 10 |
| `t < 0` | `= t + 10` | `t + 10 ∈ [0, 9]`，正好是「借了 10 之后要写的数字」 |

- 例：`t = -3` → `7`（不够减，向高一位借 10，这一位写 7）；`t = 5` → `15 % 10 = 5`
- **借位只可能是 0 或 1**（和加法的进位对称）：差值最小 `-10`，借 1 位就够。`t = (t < 0);` 把这个判断压成一行
- **顺序不能反**：`push_back` 必须在 `t = (t < 0)` **之前**，否则 `t` 已经被借位覆盖

`t` 同样是「一个变量兼两职」，只是方向跟加法相反：

| | 第一重身份 | 转换 | 第二重身份 |
| --- | --- | --- | --- |
| 加法 | 这一列的**和**（0~19） | `t /= 10` | 进位（0 或 1） |
| 减法 | 这一列的**结果**（-10~9） | `t = (t < 0)` | 借位（0 或 1） |

**④ 竖式走一遍 `100 - 99`**

```text
A = [0, 0, 1]（100 倒着存）   B = [9, 9]
i=0: t = 0 - 0 = 0 → 减 B[0]=9 → t = -9
     push((-9+10)%10 = 1)          ← 这一位写 1
     t < 0 → 借位 t = 1
i=1: t = 0 - 1 = -1 → 减 B[1]=9 → t = -10
     push(0)；t = 1                ← 又借了
i=2: t = 1 - 1 = 0 → B 已读完，不减
     push(0)；t = 0
C = [1, 0, 0] → 倒着看是 "001"
去前导 0 → [1] → 输出 1   ✓
```

**⑤ main 里整合**

```cpp
if (cmp(A, B)) {
    auto C = sub(A, B);
    for (int i = C.size() - 1; i >= 0; i--) cout << C[i];
} else {
    auto C = sub(B, A);        // 小减大 → 换过来算
    cout << '-';               // 负号先输出
    for (int i = C.size() - 1; i >= 0; i--) cout << C[i];
}
```

**易错点**

- **忘了比大小 → 答案完全错，还不报错**：`sub(1, 1000)` 里 `A = [1]`、`B = [0,0,0,1]`，循环只跑 1 次，B 的高位**根本没参与**，输出 `1` 而不是 `-999`
- **忘去前导 0**：`100 - 99` 输出 `001`
- **去零的 `while` 少写 `C.size() > 1`**：`100 - 100` 会把数组删空，输出空行
- **删的是 `back()` 不是 `front()`**：倒着存，最高位在**末尾**
- **`t = (t < 0)` 必须写在 `push_back` 之后**，顺序反了数字就错
- 加法那几条照样适用：`- '0'` 别忘了、输入无前导 0 是 `cmp` 的前提

> 题面若直接保证 `A >= B`，`cmp` 和负号整段可以省掉，只留 `sub`。
